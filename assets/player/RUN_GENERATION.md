# 달리기 원화와 조합 방식

활성 파일은 `run-stride-v7.png`이며 실제 재생은 원본8개 중 [0,1,6,4,5,2]의6개다. 양발 지지 순서와 발 기준점을 다시 등록하고 총560ms 주기를 유지했다. 새 시안/기각·프롬프트·기준점·한계는 [MOTION_GENERATION_V7.md](MOTION_GENERATION_V7.md)에 있다. 아래 D24의8프레임/동일 기준점은 이전 구현 기록이며 현재 적용값이 아니다.

## 현재 D24 — 완성 프레임 방식

2026-11-09: D23의 관절 조합은 발 위치를 계산할 수 있었지만 사용자가 본 동작은 계속 딱딱했다. 현재 활성 달리기는 `run-authored-v6.png`의 **완성된 전신 8프레임**이다. 상체·팔·다리·망토·허리띠가 함께 바뀐다. `draw_run`/`run_pose` 리그 경로는 제거했다. 기존 리그 PNG/JSON은 이전 시안 기록으로 보존하며 현재 렌더링에 쓰지 않는다.

모션 참고는 [Martial Hero / LuizMelo](https://luizmelo.itch.io/martial-hero)의 CC0 Run.png다. 제작자 페이지의 4.9/5,39개 평가는 참고 자료의 반응이며 이번 생성 원화의 평점이 아니다. 원본 ZIP과 SDL 확대 동작 연구 화면은 verification/iteration-5에만 두고 배포물에는 넣지 않는다. 원본 라이선스는 ../licenses/martial-hero-CC0.txt에 보존했다.

내장 imagegen에서 기존 디자인과 작가의 동작을 참고해 전신 시트→낮은 자세 시트→성인 비례/발 노출 보정 순으로 제작했다. 첫 시트는 높은 무릎과 기존 자세 반복 우려, 두 번째는 바지에 발이 가려지는 문제로 보류했다. 최종 요청은 낮게 기운 몸, 무릎 아래로 드러난 정강이와 두 신발, 고정된 삿갓 크기, 숨긴 얼굴, 남색 무복·적색 허리띠와 옷자락의 후속 움직임을 함께 유지하는 것이었다. 최종 PNG는 후처리 없이 원본을 복사했다.

실제 크기1774×887,4열×2행,프레임당70ms(주기.56초). 공통 몸 기준점[205,420],참고 몸 높이280px,손/장검은 기존 공통 무기 조합을 사용한다. 프레임의 불투명 영역과 손 위치는 제작 도구에서 읽어 JSON으로 작성한다. 실제 이동량으로 재생하며 벽 앞 정지와 착지 위상 초기화는 유지한다. 발소리는 이 주기의 절반마다 지상 이동 중에만 재생한다. 양방향 연속 화면과 같은 입력의 실제 시간 비교를 남기되 자연스러움·사용자 선호를 자동 합격 처리하지 않는다.

## 이전 D23 기록 — 현재 사용하지 않는 시안

2026-11-09, D23. `run-rig-v1.png`는 내장 imagegen으로 이 프로젝트의 기존 `design-master.png`(남색 무복·적색 허리띠·삿갓 검객)를 참고하여 생성했다. 원본 PNG를 그대로 복사하고 이미지 픽셀은 후처리하지 않았다.

생성 요청의 핵심: 완성 인물 8장 대신 같은 화풍의 분리 파트를 제작한다. 오른쪽을 보는 달리기 상체는 모자부터 골반까지, 짧은 회색 망토와 적색 허리띠, 골반 옆의 두 손과 칼자루만 포함한다. 칼날·다리는 상체에 그리지 않는다. 별도 가까운/먼 허벅지·정강이·신발은 곧게 편 관절 파트로 만들고 둥근 연결부와 여백을 둔다. 투명 배경, 글자·바닥·그림자 없음. 4×2 배치를 요청했으나 상체 모자가 셀을 넘었으므로 실제 격자에 억지로 맞추지 않고 독립 영역을 JSON으로 지정했다.

실제 파일은 1774×887px이다. 상체 1개·다리 파트 6개를 사용한다. 장검은 기존 `sword.png`를 손 위치에 조합한다. 원화를 8장 프레임으로 속이지 않는다. `animations.json`의 run frames는 .06초 간격의 리그 자세 샘플이며 실제 동작은 `motion.run_pose`와 `render.draw_run`이 구성한다. 상체는 고정 원화와 작은 골반 이동만 사용하므로 망토 자체의 연속 변형은 아직 없다.

채택 이유: 기존 시트와 이번 추가 시트 모두 반대 다리의 교차가 불분명했다. 같은 요청을 반복하는 대신 파트와 접지 경로를 분리하여 몸 크기·관절 길이·양발 교체·발 고정을 검증 가능하게 했다. 추가 시트 실패안은 배포 에셋에 포함하지 않고 `verification/iteration-4/rejected-run-sheet.png`에 보존했다. 실제 시간 움직임과 사용자 선호가 자동 합격했다는 의미는 아니다.
