# 접촉·달리기 보완 명세 D23

사용자: “그런거 고쳐보라고 하는데 아직도 그런거면 이상한 작업을 한게되잖아 원인을 알면 해결해봐”. 기능 검사/문서 작업에 치우친 기존 접근을 바로잡고 실제 표현과 입력의 원인을 수정한다.

## 현재 구현과 검증 계약

- core.py: 플레이어 또는 지연 검격이 새 hitstop을 만들면 해당 접촉에서 적 업데이트를 멈춘다. tick은 남은 시간을 hitstop에서 차감한 뒤 반환한다. 접촉 자세를 반드시 한 번 반환하며, 느린 프레임의 남은 시간을 다음 프레임에 몰아 처리하지 않는다. 따라서 전투 중 저프레임에서는 명목상 hitstop보다 최대 한 렌더 간격 정도 더 지연될 수 있다. 적의 확정 공격은 취소하지 않고 다음 업데이트에서 진행한다.
- 세 번째 베기 종료 전 마지막 COMBO_BUFFER(.32초) 안의 새 클릭 1회를 기존 attack_queue에 보존한다. 기존 .65초 회수를 끝내고 첫 베기를 시작한다. 이른 클릭으로 자동 4타를 만들거나 새로운 강공격을 넣지 않는다.
- run-rig-v1.png: 내장 imagegen으로 기존 주인공 참고에서 상체/허벅지/정강이/신발 분리 원화를 생성했다. PNG 픽셀은 후처리하지 않는다. JSON은 소스 영역/관절/손 위치만 지정한다.
- motion.run_pose: .48초 주기, 접지 비율 .42. 디딘 발의 뒤쪽 이동량을 실제 MOVE_SPEED와 같게 하여 일정 이동 시 월드 발 위치를 고정한다. 반대 다리는 반 주기 뒤에 이동한다. 짧은 공중 구간, 고정 길이 31px 두 관절, 작은 골반 높이 변화를 사용한다.
- render.draw_run: 원화 파트를 SDL로 조합하고 좌우 반전한다. 먼 다리는 어둡게, 상체는 고정 원화와 작은 수직 이동으로 표시한다. 별도 장검/손 덧그리기 방식은 유지한다. 다른 공격/점프/피격 에셋은 변경하지 않는다.
- build_assets.py는 새 달리기 JSON을 재생성하며 기존 run-v2 원본을 보존한다. 8개 run frames는 완성 그림 8장이 아니라 .06초 간격의 리그 샘플이다.

## 검수

test_contact_boundary.py: 동일 시점 적 반격/접촉, 100ms 프레임, 마지막 회수의 클릭/이른 클릭. 최초 3실패를 확인했고 수정 후 통과했다.
test_run_motion.py: 두 방향 접지의 월드 고정, 반 주기 다리 교체, 관절 길이, 짧은 공중 구간, 루프 닫힘/좌표 범위.
tools/combat_preview.py timing: 동일 초기 상태/클릭으로 10fps 접촉과 회수 입력을 비교한다. movement: 동일 A/D/점프 입력 전후. baseline은 수정 전 검증 ZIP에서 격리 추출했다.
전체 런타임 검사, 좌우 연속 이미지, 전후 MP4 및 실행 ZIP을 갱신한다. 실제 청취·재미·상품성·사용자 선호의 합격은 이 검사로 대체하지 않는다. 음원을 새 근거 없이 바꾸지 않는다.
