   자체 피드백·품질 개선은 `QUALITY_REVIEW.md`의 사용자 기준, 실패한 방향, 작품 비교의 확인 수준과 남은 항목을 먼저 읽는다. ‘부담스럽지 않은 칼 질감’·‘분명한 적중’처럼 함께 유지해야 하는 기준을 한 항목씩 반대 방향으로 뒤집지 않는다.

4. 영향이 크고 재현 가능한 문제부터 작은 단위로 고친다. 현재 기획 안의 수정은 계속 진행한다. 실패 재현이 가능한 경우 회귀 검사를 남기고, 단순한 문구·스타일 변경에 형식적인 테스트를 만들지 않는다.

## 증거 수준과 종료

- 모션 프레임 이미지가 정상 출력되었다는 것과 움직임이 자연스럽다는 것은 별도 판단이다. 자동 실행이 제공한 정적 이미지와 실제 시간의 영상을 구분한다.
- 피크가 낮다는 것으로 귀에 편하다고 결론 내리지 않는다. 장치·실제 음량에서 청취하지 않았다면 음원 수치 및 믹서 검증까지만 완료로 기록한다.
- 실행 불가·잠금 화면·의존성 누락은 미검증이다. 이를 통과로 숨기지 않는다. 불필요한 설치나 대규모 이미지 재생성으로 점검 범위를 늘리지 않는다.
- 예약 점검은 숨김·음소거 상태로 실행하고 사용자 앱을 조작하지 않는다. 20분 내에 검증 가능한 개선을 남기거나 이유를 기록하고 끝낸다. 일반 개발 요청의 범위를 예약 점검의 시간 제한으로 줄이지 않는다.
- 결과는 발견한 문제, 실제 수정, 검증 방법, 남은 항목을 짧게 보고한다. 진행률은 분모가 명확한 요구사항 표로 계산하며 체감 품질을 임의의 백분율로 표시하지 않는다.
