# EGM·Ponytail을 적용한 개발·검수

현재 사용자 요구와 coding-start의 작업 선택 기준이 우선한다. `.agents/references/`와 manifest는 과거에 보존한 참고 사본의 출처다. 현재 설치 상태는 스킬 목록과 실물 경로로 확인한다. 2026-11-09 재확인에서 EGM 설치 경로가 존재했다. 설치를 실제 검토 실행으로 취급하지 않는다. EGM을 선택하면 설치된 SKILL과 Codex 통합/지원 자료를 읽고 적용하며 이 문서의 과거 축약 절차로 대체하지 않는다.

## 서로 다른 역할

- [Google EGM](https://github.com/google/elephant-goldfish-model): 기존 맥락으로 명세를 쓰는 역할과 과거 대화를 받지 않은 검토 역할을 나눈다. 명세와 실제 코드를 대조해 근거 없는 전제·빠진 조건을 찾는다. 테스트·사람의 판단을 대신하지 않으며 Google 공식 지원 제품이라는 보증도 아니다.
- [Ponytail](https://github.com/DietrichGebert/ponytail): 요구를 완전히 처리하는 최소 변경을 택한다. 기존 코드→표준 기능→설치된 의존성을 먼저 확인하고, 필요한 검증·예외 처리·접근성을 삭제하지 않는다. 모델의 사실성을 보증하는 탐지기가 아니다.

## 적용 절차

1. 먼저 현재 코드와 실제 요구를 확인하고 짧은 명세를 작성한다. 현재 존재하는 것과 새로 만들 것을 표시한다. 변경 파일·분기·예외·표시 문구·검증을 정하고, 근거 없는 선호·기억은 채우지 않는다.
2. EGM을 선택한 경우 persona/standard를 읽는 별도 에이전트에 명세와 명시한 소스 목록만 준다. 현재 제공 도구의 스키마와 coding-start에 따라 부모 대화를 넘기지 않는 새 문맥 모드를 사용한다. 오래된 도구 인수명을 복사하지 않는다. 실제 완료 결과와 읽은 파일을 확인한다. 실패/미실행은 ‘문제 없음’이 아니다. 파일 시스템·호스트 AGENTS·기본 메모리까지 격리됐다고 주장하지 않는다.
3. 주 에이전트가 발견을 수락/반박/보류로 처리한다. 현재 사용자가 승인한 자율 개발 범위의 가역적 수정은 진행한다. 새 규칙·외부 게시 등 범위를 바꾸는 결정은 사용자에게 확인한다. 원본 EGM의 전체 승인·다회 수렴 루프와 이 프로젝트에 적용한 제한된 검토를 구분한다.
4. Ponytail 원칙으로 수정한다. 호출자·입력·테스트·미리보기·배포를 끝까지 연결하며 단순화를 이유로 문제를 남기지 않는다. 공개 원문의 성과 수치를 이 프로젝트의 성과로 사용하지 않는다.
5. 재현 검사와 실제 SDL 장면을 확인하고, 독립 검토를 선택한 작업은 그 결과도 확인한다. 테스트/화면/청취/재미·난이도를 분리해 보고하고, 주장→현재 파일/라인→실행 증거→미확인 항목을 연결한다. UI/모션 미감 검토와 코드 정확성 검토의 범위를 구분한다. 실패한 가설은 기록한다.

## 운영 한계

독립 리뷰어가 없는 실행에서는 주 에이전트의 점검을 ‘금붕어 독립 검토’라고 부르지 않는다. 새 채팅을 자동 생성하거나 외부로 코드를 보내지 않는다. native subagent의 공유 파일·호스트 지침 유입 가능성은 결과에 남긴다. 설치/발견만으로 워크플로 실행 성공을 보고하지 않는다. 이 절차는 환각의 완전 방지나 상업 출시 품질 인증이 아니다.
